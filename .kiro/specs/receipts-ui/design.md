# receipts-ui design

Implements `requirements.md`. Follows steering: `tech.md` (TypeScript, no framework chosen yet for UI — keeping it vanilla JS/HTML for zero build complexity and maximum hackathon transparency), `claims-and-evidence.md`, `structure.md`.

---

## Technology choice

**Vanilla HTML + CSS + JS, no framework.** Reasons:
- Zero build tooling for the site itself — `npm run receipts:build` produces static files, the site just reads them.
- No React/Vue/Svelte dependency to explain or maintain.
- Works with JS disabled for static pages (REQ-5).
- Simpler to demonstrate Kiro's role: Kiro built the data pipeline and the rendering logic.

Syntax highlighting: [highlight.js](https://highlightjs.org/) (BSD 3-Clause), loaded from CDN with integrity hash. No local copy needed.

Diff rendering: inline unified diff displayed as a `<pre>` block with coloured lines — no library needed.

## Repository layout

```
web/
  index.html          # scorecard (rendered from receipts/index.json at page load)
  receipt.html        # individual receipt (reads receipts/<db>/<schema>.<obj>.json)
  questionnaire.html  # questionnaire scan page
  style.css           # shared styles
  app.js              # shared JS: fetch JSON, render scorecard, render receipt
  questionnaire.js    # questionnaire scoring logic

receipts/
  index.json          # generated by CLI: list of all receipts with status
  <database>/
    <schema>.<object>.json   # one receipt per object

src/
  receipts/
    builder.ts        # buildReceipts(pairs, inventory, predictions): ReceiptFile[]
    schema.ts         # ReceiptFile type

  cli/
    receipts.ts       # entry point: npm run receipts:build
```

## Receipt JSON schema (`src/receipts/schema.ts`)

```ts
export interface ReceiptFile {
  database: string;
  schemaName: string;
  objectName: string;
  objectClass: ObjectClass;
  tier: Tier;
  status: "pending" | "failed" | "verified";
  code: {
    source: string;
    engineOutput: string;
    final: string;
    diff: string;
    engine: string;
    notes?: string[];
  };
  verificationSteps: Array<{
    step: number;
    label: string;
    status: StepStatus;
  }>;
  evidence: {
    pbtSeeds?: number[];
    rowsCompared?: number;
    loadTimeFindings?: string[];
    harnessVersion: string;
  };
  effort: { humanMinutes: number; engineName: string };
  predictionCell: { p50Hours: number; p90Hours: number } | null;
  builtAt: string;
}

export interface ReceiptIndex {
  builtAt: string;
  receipts: Array<{
    database: string;
    schemaName: string;
    objectName: string;
    objectClass: ObjectClass;
    tier: Tier;
    status: "pending" | "failed" | "verified";
    path: string;   // relative path to the receipt JSON
  }>;
  summary: { total: number; verified: number; pending: number; failed: number };
}
```

## Pages

### `index.html` — scorecard
- On load, fetches `receipts/index.json`.
- Renders the `predictions:score` table as HTML using data from the index.
- Each row links to `receipt.html?db=<db>&obj=<schema>.<object>`.
- If `receipts/index.json` is empty or missing, shows "No conversions yet — predictions committed, work in progress."

### `receipt.html` — individual receipt
- Reads `?db=` and `?obj=` query params.
- Fetches `receipts/<db>/<obj>.json`.
- Renders: header (name/class/tier/status badge), source/final code tabs with highlight.js, diff block, step checklist, evidence (seed, rows, load-time findings), effort, re-run command.
- "Not verified" banner if `status !== "verified"`.

### `questionnaire.html` — scan
- Pure JS form: number inputs for procedure/function/view/trigger counts, sliders for % complex / % medium.
- On submit, applies the tier P50/P90 rates from the real inventory (hardcoded from `predictions/WideWorldImporters-v1.json` medians) to estimate total hours.
- Shows a range: `P50 total: Xh — P90 total: Yh` with a disclaimer: "Judgment only — no samples from your database."
- No network request, no data storage.

## Key design decisions

1. **No build step for the site.** `web/*.html` files reference `web/app.js` directly. `receipts:build` generates the JSON; the HTML just fetches it. Visitors see the same JSON the CLI produced.
2. **Receipt JSON is the source of truth.** No numbers are typed into HTML.
3. **Questionnaire rates are hardcoded from real predictions.** Once Steve fills in predictions, the questionnaire uses those P50/P90 values so the estimate reflects real measured data.
4. **Highlight.js from CDN with SRI hash.** Avoids vendoring a library while keeping the page functional offline if the CDN is down (graceful degradation: code shows as plain text).
